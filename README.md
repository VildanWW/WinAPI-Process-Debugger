# Process Memory Analyzer & Monitor (GoldSrc Engine)

Инструмент динамического анализа памяти процессов и автоматизации взаимодействия с адресным пространством приложений (на примере игрового движка GoldSrc / CS 1.6).

## 📌 Описание проекта

Проект представляет собой внешний инструмент (**External Monitor**), работающий в изолированном адресном пространстве Windows. Взаимодействие с целевым процессом осуществляется исключительно на низком уровне через системные вызовы WinAPI, без инжекции сторонних динамических библиотек (DLL). 

Разработка велась в научно-образовательных целях для глубокого изучения механизмов виртуальной памяти ОС Windows, управления процессами, системных хуков и реверс-инжиниринга структур данных.

---

## 🛠️ Технологический стек

* **Язык программирования:** C++ (стандарт C++11/C++14/C++17)
* **API Операционной системы:** WinAPI (`OpenProcess`, `ReadProcessMemory`, `WriteProcessMemory`, `VirtualAllocEx`)
* **Инструменты анализа:** x64dbg, Cheat Engine (для поиска динамических указателей и базовых смещений)
* **Архитектура:** Многопоточное консольное приложение со сторонним оверлеем

---

## 🚀 Реализованный функционал и технические детали

### 1. Модуль визуализации объектов (Entity Tracking & WorldToScreen)
* **Реализация:** Парсинг динамического списка сущностей (`Entity List`) в памяти процесса в реальном времени. Программа считывает трехмерные координаты объектов (`X, Y, Z`) из структуры процесса.
* **Математический аппарат:** Спроектировано и реализовано матричное преобразование (**WorldToScreen**) на основе матрицы вида/проекции игрового движка для корректного перевода 3D-координат пространства в 2D-координаты экрана монитора.
* **Оптимизация:** Чтение памяти оптимизировано для минимизации задержек системных вызовов (`RPM`), что обеспечивает отрисовку графических маркеров с частотой обновления < 1 мс.

### 2. Модуль автоматического наведения (Векторный контроллер)
* **Реализация:** Алгоритм асинхронного вычисления векторов направления взгляда (`ViewAngles`) на основе тригонометрических расчетов (арктангенсы разности координат).
* **Архитектурное решение:** На текущем этапе наведение производится на статический центр модели с заданным смещением (`offset`). В следующей, внутрипроцессной (Internal) версии проекта запланирован прямой разбор структуры массива костей (`Bone Matrix`) для динамического позиционирования.

### 3. Модуль автоматизации ввода (Фильтрация системных флагов)
* **Реализация:** Перехват и синхронизация ввода на основе циклического чтения флага состояния физической модели персонажа в памяти (`FL_ONGROUND`). Позволяет автоматизировать действия мыши/клавиатуры со строгими таймингами в зависимости от физического статуса модели в движке.

### 4. Компенсация динамических смещений (Система стабилизации)
* **Реализация:** Разработан алгоритм перехвата векторов отдачи оружия и динамической корректировки углов обзора в памяти процесса для компенсации разброса.
* **Результат:** Достигнуто существенное повышение кучности распределения координат попаданий.

## 📈 Направления для дальнейшего развития (R&D)

В ходе разработки были исследованы ограничения внешнего подхода (External), такие как задержки при интенсивных вызовах `ReadProcessMemory` и сложность синхронизации с кадровой частотой игры. 

Следующим этапом планируется переход к **Internal-разработке**:
1. Написание собственной DLL для инжекции в процесс.
2. Реализация виртуальных хуков функций (VMT Hooking) и перехват функций отрисовки (DirectX / OpenGL).
3. Прямой доступ к структурам данных движка без использования WinAPI вызовов чтения/записи памяти для максимального быстродействия.

> ⚠️ **Важное примечание по совместимости:** 
> Проект жестко завязан на конкретные структуры данных и динамические смещения (offsets) в памяти. Разработка и тестирование велись на чистой Non-Steam сборке игры (пиратке), которая технически полностью идентична оригинальной лицензионной Steam-версии движка GoldSrc со следующими параметрами:
> * **Protocol version:** 48
> * **Exe version:** 1.1.2.7/Stdio (cstrike)
> * **Exe build:** 20:10:31 May 7 2025 (10422)
> * **Branch:** master (2.5.6.0)
>
> При запуске на других пиратских сборках (например, старых No-Steam патчах v43) или обновленном движке адреса памяти изменятся, что приведет к падению программы (`Access Violation`). Данный код рекомендуется использовать как теоретическую базу и источник готовых алгоритмов для реверс-инжиниринга.
> 
> *В будущем в раздел Releases или по внешней ссылке будет выложен архив с точным слепком этой сборки игры для удобства тестирования и анализа.*
